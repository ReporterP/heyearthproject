# 11 · Новое: как добавлять, не ломая «Канон»

Правило одно: **сначала спецификация, потом код**. Новая кнопка, состояние, страница или анимация сначала появляются строкой в этих файлах (и классом в `hiearth.css`, если нужен новый вид), затем в JSX. В одном коммите или PR.

## 1. Порядок для любой доработки

1. **Найти аналог.** Поиск по 02 (компоненты) и 06–10 (экраны). В 9 случаях из 10 нужное уже есть: карточка с заголовком, строка истории, `alert`, `empty`, `copy`, `dl`, `set`.
2. **Определить режим поверхности.** Persuade (главная, B2B-лендинг, приглашение) — допустимы крупная типографика, фирменные элементы, `rise`. Operate (кабинет, оплата, настройки) — плотность, предсказуемость, движение только как отклик. Read (помощь, документы) — `toc`, `doc`, `num`.
3. **Описать в спецификации:** паспорт, данные, элементы с показом/действием/состояниями, действия, состояния экрана (загрузка, пусто, ошибка), телефон. Обновить сводную таблицу 03 §11, если появилось условие показа.
4. **Новый компонент** (только если аналога нет): анатомия, варианты, таблица состояний (default/hover/focus/active/disabled/loading/error/selected), показ/скрытие, движение (строка в 04), доступность, тексты, «нельзя», React-API — раздел в 02. Классы — в `hiearth.css`, блок своего раздела, все значения через токены.
5. **Новый токен** (крайний случай): строка в 01 с назначением и запретами + переменная в `:root`. Новый цвет должен иметь контраст ≥ 4.5:1 на всех поверхностях, где используется.
6. **Тексты** — по 05; новые ошибки и статусы — в каталоги 05 §6–7.
7. **Код:** компонент из `components/`, страница собирает их; никакой стилизации компонентов на уровне страницы. Локальные классы допустимы только для раскладки одной страницы, с префиксом страницы (`lp-` главная, `biz-` B2B-лендинг), в CSS-модуле этой страницы и только на токенах. Как только узор нужен второй странице — он переезжает в `hiearth.css` и в 02.
8. **Проверка** — §4 ниже.
9. **Макет:** если изменение видимое и новое (новый экран, новое состояние), добавить или обновить артборд на холсте экранов и опубликовать холст. Небольшие изменения внутри существующего компонента — достаточно спецификации.

## 2. Решения по умолчанию

| Нужно… | Используйте |
|---|---|
| сообщить об успехе действия без места на странице | тост успеха |
| сообщить об ошибке поля | `field__error` |
| сообщить о проблеме блока/страницы | `alert--bad` с «Повторить/Обновить» |
| объяснить условие перед действием | `alert--info` / `alert--warn` |
| подтвердить опасное действие | Dialog с `btn--danger` |
| показать пустой список | `empty` с ёжиком `search` |
| показать загрузку | скелетон > 300 мс |
| показать деньги/дни крупно | `flap` |
| показать статус | `badge` из таблицы 05 §6 |
| показать ID | `tag--chip` / `copy` с mono |
| дать скопировать | `copy` |
| настройку вкл/выкл | `switch` (без кнопки «Сохранить») |
| выбор из 2–4 | `seg` |
| выбор из 5+ | `sel` или список строк |
| вторичный переход | `link` или `btn--ghost` |
| длинный текст | `doc` |
| инструкцию | `num` |
| новую страницу кабинета | `AppShell` + `page-head` + карточки в сетке 12 |
| новую страницу шага/результата | узкая шапка `back` + `mini`/`res` или колонка 560–760 |

## 3. Запрещено (STOP-лист)

Если в коде сайта встречается что-то из этого — остановиться и исправить до коммита:

- Сырые цвета (`#…`, `rgb(…)`) и палитра Tailwind (`bg-slate-*`, `text-gray-*`, `bg-zinc-*`, `bg-green-500` и т.п.) в `site/src` — только `var(--…)` и классы `hiearth.css`.
- Шрифты кроме Manrope и JetBrains Mono (`Inter`, `Roboto`, `Lora`, `Raleway`, системные как основные).
- Светлая тема, переключатель темы, `prefers-color-scheme: light`.
- Тени на карточках/кнопках (`shadow-*` Tailwind, свои `box-shadow`), цветные свечения, градиентный текст, стекло как украшение.
- Надписи-«брови» мелким капсом над заголовками; цветная полоса слева у карточек/алертов.
- Вторая primary-кнопка на экране.
- Слово «VPN», названия протоколов, «обход блокировок» в любом тексте интерфейса, `title`, `alt`, мета-тегах.
- Выдуманные цифры, отзывы, страны, скорости; захардкоженные названия и цены тарифов.
- `window.confirm`, `alert`, `prompt`; свои тултипы; свой выпадающий список вместо `select`.
- Анимации не из каталога 04, анимации при прокрутке, бесконечные анимации вне разрешённого списка.
- Ёжик больше одного на экране, ёжик с репликой, ёжик в кнопке.
- `import.meta.env.VITE_API_BASE` (оба приложения используют `const API_BASE = ''`).
- Новый UI без строки в спецификации.

## 4. Готово, когда

- [ ] Спецификация обновлена в том же коммите (элементы, действия, состояния, 03 §11, каталоги 05).
- [ ] Есть все состояния: загрузка, пусто, ошибка, успех; у каждой кнопки — `loading`; у каждого условия — обе ветки.
- [ ] Клавиатура: Tab-порядок, видимое кольцо фокуса, Esc закрывает слои, фокус возвращается.
- [ ] Доступность: метки у полей, `aria-label` у иконок-кнопок, статусы не только цветом, `aria-live` у тостов и копирования, ёжик `aria-hidden`.
- [ ] Проверено на 390, 768, 1024, 1440 px — без горизонтальной прокрутки, кнопки на телефоне 48 px.
- [ ] `prefers-reduced-motion` — смысл сохраняется.
- [ ] `cd site && npm run build` — без ошибок.
- [ ] `impeccable detect --json <изменённые файлы>` — 0 предупреждений (допустимые советы: пружинная кривая и русские тире).
- [ ] Скриншот изменённой страницы сравнён с артбордом (одна страница — один скриншот).
- [ ] В тексте нет слов из STOP-листа (`grep -ri "vpn\|vless\|shadowsocks\|xray\|hysteria" site/src` пусто, кроме кода/комментариев).

## 5. Когда спецификация мешает

Если правило здесь явно хуже для человека в конкретном месте — не обходите его молча. Предложите правку владельцу: что меняем, почему, где ещё это затронет. После «да» — правка спецификации, затем код. Изменения направления (цвета бренда, шрифты, тема, фирменные элементы) — только решением владельца и через `impeccable` (обновить `DESIGN.md`).
