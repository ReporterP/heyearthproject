# 03 · Поведение

Общие правила, которые действуют на каждой странице. Экранные файлы (06–10) описывают только отличия.

## 1. Наведение (hover)

- Наведение подсказывает, что элемент кликабелен. У некликабельного (карточка без ссылки, бейдж, орб как кнопка) наведения нет, кроме лёгкого `scale(1.02)` ядра орба.
- Что меняется: фон на шаг светлее (`--bg-hover`) или рамка (`--line-hover`/`--line-strong`), текст `--fg-muted` → `--fg`. Подъём на 2 px — только у целиком кликабельных карточек (`card--link`, `plan`, `dl`).
- Длительность 120–200 мс `--ease-out`, на уход — такая же.
- На сенсорных экранах hover не должен «залипать»: эффекты подъёма оборачиваются в `@media (hover:hover) and (pointer:fine)` при реализации; цвет фона на тап допустим.
- Тултипов (всплывающих подсказок) на сайте нет. Нужное пояснение пишется видимым текстом рядом. Исключение — нативный `title` у столбиков графика и у `tag--chip`.

## 2. Фокус и клавиатура

- Фокус виден всегда при навигации с клавиатуры: кольцо 2 px `--info`, отступ 2 px, радиус по элементу (`:focus-visible`). У полей — синяя рамка + мягкое кольцо 3 px. Мышью кольцо не появляется.
- Порядок Tab = порядок чтения: шапка → основное → боковые блоки → футер. На каждой странице первым идёт `a.skip` «Перейти к содержимому» → `#main` (спрятана над экраном, по фокусу выезжает в левый верхний угол).
- `Enter` отправляет форму из любого поля; `Space` переключает чекбокс/переключатель; стрелки двигают выбор в `seg` и `amounts`.
- `Esc` закрывает диалог и мобильное меню. Фокус после закрытия возвращается к открывшему элементу.
- В диалоге и открытом меню фокус зациклен.

## 3. Нажатие (active)

Кнопки сжимаются до `scale(.97)` за 120 мс — тактильный отклик. Строки и карточки при нажатии не сжимаются. Двойной клик по кнопке отправки не создаёт два запроса: с первого клика кнопка в `loading`.

## 4. Выключено или скрыто

| Ситуация | Решение |
|---|---|
| Действие станет доступно, когда человек что-то сделает на этой же странице | показать `disabled` + подпись-причину |
| Действие невозможно в текущем состоянии аккаунта (нет подписки, нет почты) | не показывать; вместо него — подсказка или другое действие |
| Действие запрещено ролью (B2B: сотрудник не может пополнить) | не показывать кнопку; одна строка `t-xs subtle` «Пополнение доступно администратору и биллинг-менеджеру» |
| Данных ещё нет (загрузка) | скелетон на месте блока; кнопки блока не показываются до данных |
| Функция выключена на сервере (`b2b_enabled`, промокоды) | весь блок не рендерится, маршрут отвечает 404 |

## 5. Загрузка

| Что грузится | Как показываем |
|---|---|
| Первая загрузка страницы/блока | скелетон, если дольше 300 мс; до этого — пустое место нужной высоты |
| Действие по кнопке | кнопка `loading`, остальные кнопки формы `disabled` |
| Переключатель / select | новое положение сразу + `disabled` до ответа (оптимистично) |
| Повторная загрузка того же блока (фильтр, период) | старые данные `opacity .5`, без скелетона |
| Ожидание внешнего события (оплата, открытие приложения, письмо) | `spinner` или `timeline is-now` + текст «что ждём» и «что можно сделать» |
| Переход между страницами | без глобального индикатора; новая страница сразу рисует свой каркас со скелетонами |

Ни один экран не остаётся пустым больше 300 мс без объяснения.

## 6. Ошибки

| Тип | Где | Пример |
|---|---|---|
| Ошибка поля (валидация, сервер про поле) | `field__error` под полем + `is-invalid` | «ИНН должен содержать 10 цифр (юрлицо) или 12 (ИП)» |
| Ошибка отправки формы | `alert--bad` над кнопкой отправки | «Аккаунт не найден. Проверьте ID…» |
| Блок не загрузился | на месте блока: `alert--bad` с `link` «Обновить» (перезапрос блока, не страницы) | «Тарифы недоступны. Не удалось загрузить список. Обновить» |
| Вся страница не загрузилась | `empty` с `hh--worried`: «Не удалось загрузить данные» + `btn--secondary` «Повторить» | |
| Действие без места на странице (переключатель, копирование, select) | `toast--bad` | «Не удалось изменить автопродление» |
| Сессия истекла (401) | без сообщения на текущей странице: переход на `/login?next=<текущий путь>`, на входе `alert--info` «Сессия закончилась — войдите снова» | |
| Нет сети | `toast--bad` «Нет соединения с интернетом» один раз; после восстановления — тихий перезапрос | |
| 404 ресурса (платёж, код) | на месте контента — `alert--bad` или `mini` с объяснением и кнопкой назад | «Платёж не найден или принадлежит другому пользователю» |
| 5xx | как «блок не загрузился»; текст без кодов и английского | |

Текст ошибки: **что случилось** (жирно) + **что делать**. Никогда не показываем `error.message` с сервера сырым, если он по-английски или технический — только из каталога в 05.

## 7. Подтверждения

Диалог подтверждения нужен только для: выхода из аккаунта, удаления (почта, сотрудник), отправки заявки на возврат (это форма). Оплату не подтверждаем отдельным диалогом — шаг «Оформление» и есть подтверждение. Отмена — всегда слева и всегда безопасна.

## 8. Копирование

Всё, что человек может захотеть вставить в другое место (ID, ссылка подписки, ссылка-приглашение, ссылка на счёт, код, ID платежа), копируется одной кнопкой. Отклик — `is-copied` на 2 с у самого поля; если поля нет (`tag--chip`, «Скопировать ссылку» на карточке друга) — тост «… скопирован(а)» и текст кнопки на 2 с меняется на «✓ Скопировано».

## 9. Формы

- Валидация на клиенте повторяет серверную (длины, форматы), но сервер — последний судья.
- Кнопка отправки всегда активна, кроме двух случаев: нет изменений (настройки — «Нет изменений») и не дано обязательное подтверждение (галочка «Я сохранил…»). В остальных случаях нажатие показывает ошибки полей и ставит фокус на первое неверное поле.
- После успешного сохранения поля остаются заполненными новыми значениями, пароль очищается, тост «Изменения сохранены».
- Ничего не теряется при ошибке: введённое остаётся в полях.
- Необязательные поля помечены «(необязательно)», обязательные не помечаются звёздочкой.
- Автофокус только на страницах, где форма — единственное содержание (вход). На регистрации и в кабинете — нет.

## 10. Навигация и переходы

- Смена страницы — прокрутка в начало (кроме якорей и «назад» браузера).
- Защищённые страницы (кабинет, оплата) гостя отправляют на `/login?next=…`; после входа — возврат на `next`.
- Вошедшего пользователя `/login` и `/register` перенаправляют в `/dashboard`.
- Якорные ссылки на главной прокручивают плавно (`scroll-behavior:smooth`, выключено при reduced motion).
- Возврат из ЮKassa ведёт на результат оплаты; кнопка «Назад» браузера на результате не возвращает в виджет.
- Ссылки на внешние магазины приложений — обычный переход; ссылка `happ://…` — через страницу `/connect?sub=…` (см. 08).
