# Спецификация «Канон» — как устроен каждый элемент, экран и действие

Это **обязательный** документ для любой работы над `site/` (маркетинг, кабинет, оплата, B2B): пересборка, доработка, переделка, новая страница, новая кнопка. Если что-то на сайте выглядит или ведёт себя не так, как здесь написано, — это баг сайта или пробел спецификации, а не «вариант».

Не относится к `admin_web/` (у админки своя тема Linear, см. корневой `CLAUDE.md`) и к `flutter-app/`.

## Источники истины (по старшинству)

1. **`../hiearth.css`** — токены и все классы. Код сайта берёт цвета, шрифты, радиусы, тени и анимации только отсюда.
2. **Эта папка `spec/`** — поведение: состояния, показ/скрытие, действия, анимации, тексты. Где CSS и спецификация расходятся, правят оба файла в одном коммите.
3. **Холст экранов** — https://claude.ai/artifact/U6TEr9jSpR1cuRk9XcS5Li (31 макет, страница `ds-states` — все состояния компонентов).
4. **Артефакт дизайн-системы** — https://claude.ai/artifact/5GptLe8fU1HxtyavML6SSh (бренд-бук, токены, карточки компонентов).
5. `PRODUCT.md` и `DESIGN.md` в корне репозитория — продуктовая правда и краткие правила.

## Как пользоваться

- **Делаете экран** → откройте его раздел в 06–10, сверху вниз реализуйте таблицу элементов, затем таблицу действий, затем все состояния экрана. Компоненты берите из 02 с их классами.
- **Делаете новый элемент** → сначала 11-extending: найдите существующий компонент; если его нет — допишите его в 02 (и в `hiearth.css`) **до** кода страницы.
- **Меняете поведение** (например, когда показывать кнопку) → поменяйте строку в таблице экрана и сводную таблицу показа/скрытия в 03 в том же коммите, что и код.
- **Ревью** → сверяйте с чек-листом в конце 11-extending.

## Нотация

- Классы пишутся без префикса `.he` (`btn btn--primary`), но в CSS все они живут под `.he` — корневой `<div className="he">` обязателен.
- **Показ:** условие, при котором элемент есть в DOM. «Скрыт» = не рендерится (или `hidden`), если не сказано «прозрачный/невидимый».
- **Действие:** `триггер → что уходит в API → что видит человек при успехе → что при ошибке`.
- Состояния называются одинаково везде: `default`, `hover`, `focus` (= `:focus-visible`), `active` (нажатие), `disabled`, `loading`, `error`, `selected`/`checked`, `empty`.
- Ширины: **телефон** ≤640 px, **планшет** 641–1024 px, **десктоп** ≥1025 px. Эталонные макеты: 1440 и 390 px.
- `Тексты в «ёлочках»` — точные строки интерфейса. Суммы, даты, названия тарифов в примерах — из демо-данных, в коде они приходят из API.
- Ссылки на API — как в текущем коде сайта (ветка `cleanup/2026-11-13`).

## Пять правил, которые нельзя нарушить

1. Только тёмная тема. Только токены из `hiearth.css`. Только Manrope и JetBrains Mono.
2. Одна зелёная (primary) кнопка на экран или в открытом диалоге.
3. Слово «VPN», названия протоколов и «обход блокировок» не пишем нигде в интерфейсе.
4. Ничего не выдумываем: ни отзывов, ни числа пользователей, ни скоростей, ни стран, кроме Нидерландов. Цены, названия тарифов, бонусы и лимиты приходят из API.
5. У каждого действия есть видимый отклик (загрузка, успех, ошибка), у каждого списка — пустое состояние, у каждой загрузки — состояние ошибки.
