Пользователь описал баг: **$ARGUMENTS**

Лёгкий workflow без PRD/плана. Для багов, которые укладываются в <30 мин и одно место изменения.

## Шаг 1: Systematic debugging

Вызови `superpowers:systematic-debugging`:
1. Прочитай сообщение об ошибке / repro steps
2. Найди корневую причину (не только симптом)
3. Изучи 1-2 похожих рабочих места в коде для сравнения
4. Сформулируй гипотезу

**Стоп-правило:** если после 3 неудачных попыток фикса проблема не решена — эскалируй до `/feature` (нужен полноценный план).

## Шаг 2: Мини-запись в Beads (если настроен)

```bash
bd create "bugfix: <короткое описание>" -t bug
```

Это обязательно только если баг найден во время другой задачи — тогда зависимость `discovered-from`:
```bash
bd dep add <new-bug-id> <current-task-id> --type discovered-from
```

## Шаг 3: Исправить

Внеси минимальное изменение, исправляющее корневую причину. **Не рефакторь** попутно — только то, что относится к багу.

## Шаг 4: Верификация

Вызови `superpowers:verification-before-completion`. Обязательные проверки:
- `go build ./...` проходит (для Go изменений)
- `fvm flutter analyze` без новых ошибок (для Flutter)
- `npm run build` (для admin_web / site)
- Фактический запуск команды, которая воспроизводила баг → теперь работает

Покажи **полный вывод команды верификации** пользователю, не сокращая.

## Шаг 5: Закрыть

Если Beads использовался:
```bash
bd close <id> --reason "fixed: <что сделал> | verified by <какая команда>"
```

Коротко резюмируй пользователю: что было не так, что поменялось, чем доказал что работает.
