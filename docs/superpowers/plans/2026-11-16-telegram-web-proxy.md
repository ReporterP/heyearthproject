# Фаза T — Telegram WEB-прокси (официальный `tproxy-server`) — 16.11.2026

Эта фаза дополняет `2026-11-13-cleanup-plan.md`. Выполнять после текущей задачи (B8) и до финала. Подписки пользователей не меняются. Меняется только кабинет: в нём появляется новая ссылка.

## Почему

- **Классический MTProxy с FakeTLS** у нас на exit — это «Telegram-прокси». С 1 апреля 2026 ТСПУ распознаёт его по поведению самого клиента Telegram. Сервером это не чинится (telemt#617, tdesktop#30733).
- **WEB-прокси** — новый официальный тип прокси Telegram, вышел в августе 2026.
  - Приложение сохраняет MTProxy-кадрирование, но отправляет все соединения через свой WebView: обычный HTTPS long-poll или WebSocket к настоящему сайту с настоящим сертификатом.
  - TLS-рукопожатие делает браузерный движок.
  - Без «ссылки-моста», вычисленной из секрета, сервер отдаёт обычный сайт.
- **Клиенты на 16.11.2026:**
  - Telegram Desktop — с 7.1.1;
  - Android — бета 12.10.2 (есть неподтверждённые сообщения о релизе);
  - iOS — официального клиента нет.
  - Сервер помечен как proof-of-concept.
- **Источники:** https://github.com/telegramdesktop/tproxy-server (README, PROTOCOL.md, BASE_PATH.md, HARDENING.md) и разбор интеграции https://github.com/getmeridian/meridian/issues/98 (проверено на живой VM 19.10.2026).

## Решения владельца (16.11)

1. **Адрес:** `tg.hiearth.ru`, хранится настройкой. Когда владелец купит нейтральный домен, адрес меняется в админке без переделки.
2. **Ссылку видят** все с активной подпиской, как сейчас с MTProto.
3. **Старый MTProto-прокси** остаётся запасным: в кабинете он второй строкой «для iOS и старых версий Telegram».

## Схема

```
Telegram (WEB-прокси) ──HTTPS 443, SNI tg.<домен>──▶ вход в РФ (nginx stream, PROXY) ─┐
                                                   или Hub напрямую ─────────────────┤
Hub: nginx stream (SNI-карта) → http nginx (8443 / 8446 realip) server tg.<домен>
     location / → 127.0.0.1:8080  tproxy-server (relay; admin 127.0.0.1:8081)
                                   └→ 127.0.0.1:2398 официальный MTProxy → Telegram DC
```

- **Сервер.** Всё работает на Hub. Путь от пользователя тот же, что у `go.<домен>`: A-записи `tg.<домен>` указывают туда же, куда `go.<домен>` (входы, при необходимости и Hub). Так прокси работает и на мобильном интернете через входы.
- **Почему не на exit.** Exit не пройдёт мобильные белые списки, а на его 443 уже стоит запасной канал.
- **Если у Hub не будет связи с Telegram DC.** Проверить middle-end MTProxy (см. «Проверка»). Если Telegram DC из российского датацентра окажутся задушены, вариант 2 — тот же стек на exit, а на Hub в stream-карте TLS-passthrough `tg.<домен>` → exit:443.

## Задачи

### T1. Сборка и установка на Hub (идемпотентно, из админки и CLI)

- **`tproxy-server`:**
  - собирается локально из закреплённого коммита `telegramdesktop/tproxy-server` (прогнать его `go test ./...`);
  - кладётся артефактом `artifacts/tproxy-server` с sha256 — по тому же образцу, что node-agent в B7;
  - на Hub устанавливается в `/usr/local/bin/tproxy-server`.
- **Официальный MTProxy:**
  - строится на Hub из закреплённого коммита `f36d8af769ffaeac36978d38c2c0f6d1104c2137` пользователем `mtproxy`, архив сверяется по контрольной сумме (как в upstream `deploy/install-mtproxy.sh`);
  - `proxy-secret` и `proxy-multi.conf` берутся по HTTPS;
  - таймер обновления `refresh-mtproxy-config` — раз в сутки.
- **Systemd-юниты** берутся из upstream `deploy/` с их жёсткими ограничениями (`ProtectProc=invisible`, `ProcSubset=pid`). Своего Caddy нет, вместо него наш nginx.
- **Конфиги** (golden-тесты на рендер):
  - `/etc/tproxy-server/config.json`: `public_hostname`, `public_dir`, лимиты по умолчанию;
  - `profiles.json`: один профиль, `carrier_mode: "https"`, `backend 127.0.0.1:2398`, режим 0400;
  - `token.key`: 32 байта, создаётся один раз, хранится, попадает в бэкап.
- **Секрет** — в `app_settings` `tg_webproxy_secret`, 32 hex.
  - Никогда не печатать и не логировать.
  - «Сменить секрет» в админке переписывает профиль и `mtproxy.env`, перезапускает relay и MTProxy. Старые ссылки после этого перестают работать — предупредить в диалоге.
- **Порты 2398, 8080, 8081, 8888** только на loopback. ufw их не открывает. nft-таблица из upstream (`tproxy_backend`) — второй рубеж.
  - Проверить, что egress-guard Hub не мешает MTProxy ходить к Telegram, а relay — к 127.0.0.1:2398.
- **Установку запускает** рецепт ядра провижининга на Hub (`State.Hub` = LocalRemote) по кнопке «Установить / обновить» в админке. Плюс шаг в CLI для чистого Hub.

### T2. nginx и маршрутизация

- **SNI-карта stream.** `tg.<домен>` ведёт в http nginx — как остальные имена сайта (`RouterSiteNames`). Добавлять из настройки, а не захардкоженным списком.
- **`server` для `tg.<домен>`** на обоих входах http nginx: 8443 и 8446 с `proxy_protocol` и realip.
  - **Проксирование:**
    - `location / { proxy_pass http://127.0.0.1:8080; }` с HTTP/1.1, заголовками `Upgrade` и `Connection`;
    - `proxy_buffering off; proxy_request_buffering off; client_max_body_size 0;`;
    - таймауты чтения больше long-poll — 75 с.
  - **Заголовки:** `proxy_set_header Host $host;`, `X-Forwarded-For $remote_addr` — ровно один адрес, relay отвергает список.
  - **Журнал:** `access_log off;`. URI `/?bridge=…` — это учётные данные.
  - **TLS:** `ssl_ecdh_curve X25519:prime256v1;`. Android не работает, когда сервер предлагает X25519MLKEM768 (tproxy-server#16). На Ubuntu 24.04 его и так нет, но зафиксировать явно.
  - **Чего не добавлять:** site-заголовки `X-Frame-Options`, COOP/COEP и CSP. Мост ставит свой CSP.
- **Сертификат.** certbot выпускает его так же, как для остальных имён — после того как владелец поставит A-запись. Без записи шаг ждёт и показывает в админке, какую запись добавить.
- **Сайт-заглушка** (`public_dir`): нейтральная статическая страница о вымышленной небольшой студии.
  - Не лендинг HiEarth и не шаблон из интернета: одинаковый стартовый сайт у многих операторов — подпись для активного зондирования.
  - Состав: index, about, 404, стили, favicon.
  - Генерируется один раз и коммитится как ассет.

### T3. Админка «Telegram»

Карточка в разделе MTProto, который переименовать в «Telegram».

- **WEB-прокси:**
  - вкл/выкл (`tg_webproxy_enabled`);
  - адрес (`tg_webproxy_host`, по умолчанию `tg.<домен сайта>`);
  - «Сменить секрет» с подтверждением;
  - кнопка «Установить / обновить».
- **Состояние** — из `127.0.0.1:8081/healthz`, `/readyz`, `/metrics`:
  - живые сессии и потоки;
  - готовность backend;
  - MTProxy middle-end: число строк «Disconnected from RPC Middle-End» за 5 минут;
  - срок сертификата;
  - DNS: A-записи `tg.<домен>` совпадают с адресами входов или Hub.
- **Классический MTProto** — прежний блок, подписан «Запасной: iOS и старые версии Telegram».
- **Монитор:** проба `readyz` раз в минуту; тревога, если WEB-прокси включён, а `readyz` не 200 три раза подряд.

### T4. Кабинет

- **`GET /user/mtproto`** — только при активной подписке, как сейчас — возвращает и `web`, и `classic`:
  - `web: {link, server, secret}`;
  - `link = https://t.me/webproxy?server=<host>&secret=<secret>`;
  - если t.me не открывает эту ссылку — запасной вариант `tg://webproxy?...`.
- **Блок «Telegram» в кабинете:**
  - первым — «WEB-прокси (Telegram Desktop 7.1+, Android — обновите Telegram)» с кнопкой «Подключить», «Скопировать адрес и секрет» и подсказкой, куда их вставить;
  - вторым — «Классический (для iOS и старых версий)».
- **Не показывать** адрес и секрет WEB-прокси как пару для классического MTProto. Если ввести их в форму MTProto на 443, Telegram пошлёт обычный MTProxy, который ищет ТСПУ.

## Проверка на проде

1. `curl https://tg.<домен>/` → сайт-заглушка, сертификат валиден. `curl 'https://tg.<домен>/?bridge=wrong'` и `/?bridge=wrong&x=1` → та же главная. Произвольный путь → 404 заглушки.
2. С exit или через физическую сетевую карту: TCP 2398, 8080, 8081 и 8888 на адресах Hub недоступны.
3. `journalctl -u mtproxy --since -5min | grep -c 'Disconnected from RPC Middle-End'` ≈ 0. `curl 127.0.0.1:8081/readyz` → 200.
4. В журнале nginx нет строк с `bridge=`.
5. Владелец проверяет из Telegram Desktop 7.1+: на Wi-Fi и через вход в РФ (раздача с мобильного). В `/metrics` растут сессии и потоки.
6. Подписки — снимок до и после совпадает: фаза их не меняет.

## За владельцем

- **DNS:** A-записи `tg.hiearth.ru` туда же, куда `go.hiearth.ru`. Исполнитель просит владельца сделать это и ждёт, пока записи заработают.
- **Когда купит нейтральный домен** — сменить адрес в админке, поставить его A-записи и выпустить сертификат.

## Откат

Выключатель скрывает ссылку и останавливает relay и MTProxy. Блок `server` для `tg.<домен>` удаляется из nginx при выключении.
