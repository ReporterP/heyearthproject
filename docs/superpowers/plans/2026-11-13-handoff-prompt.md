Ты исполняешь план доработок HiEarth. HiEarth — VPN/прокси-сервис: Go-бэкенд, React-админка `admin_web`, React-сайт `site`. Flutter-приложение (`flutter-app`) не трогай. Владелец пишет по-русски, отвечай ему по-русски, коротко и по делу.

## Цель

Полностью и критически реализовать план `docs/superpowers/plans/2026-11-13-cleanup-plan.md` (фазы A → W → R → B → C → D → E) и выкатить всё на прод. Работа закончена, когда каждая задача сделана, проверена на проде и закрыта.

Серверы владелец добавит через админку сам, в самом конце. К этому моменту сценарий добавления exit и входа в РФ (фаза B) должен работать безупречно.

## Режим работы

Владелец явно разрешил работать без остановок. Это разрешение перекрывает правило CLAUDE.md «остановись после фазы».

- Не останавливайся между фазами и не спрашивай подтверждения на задачи из плана. После каждой фазы — короткий отчёт в чат: что сделано и чем проверено на проде. Затем сразу следующая фаза.
- Спрашивай владельца только в двух случаях:
  - нужно его решение, которого нет в плане: бизнес-правило или деньги клиентов сверх плана;
  - нужно действие, которое может сделать только он: ключи ЮKassa, DNS, покупка серверов, пароли.
- Перед финалом всё выкачено, все задачи эпика `heyearthproject-ootr` в Beads закрыты с доказательствами.

## Прод

Hub — единственный сервер с API, БД и админкой. Exit 2 стоит в Амстердаме. Переезда Hub нет.

- **Деплой API:** точный коммит из чистого worktree + `quick_deploy.go`.
  - До и после деплоя — снимок подписок `scripts/prod/snap_subscriptions.sh` и diff.
  - Подписка меняется намеренно только в задачах, где это прямо написано: A7 (лимиты), D7 (удаление «Пальмы»), W4/W7 (объявления). Тогда объясни разницу в отчёте.
- **Админка** — через `quick_admin_web.go`.
- **Сайт.** Сначала сделай задачу D3: атомарный `--vue-site`. Сейчас эта команда удаляет живой сайт до загрузки нового. Только после D3 деплой сайта.
- **Любое изменение данных на проде:**
  - бэкап затронутых строк в `<table>_bak_20261113`;
  - транзакция;
  - `ON_ERROR_STOP`.
- **A1, перед баном.** Покажи в отчёте список — только префиксы ID, без личных данных. Не бань тех, кому срок выставили вручную.
- **После каждого деплоя:**
  - health и журнал без panic;
  - проверка самой функции на проде: curl, SQL или админ-API через `scripts/prod/admin_token.sh`;
  - для интерфейса — один скриншот изменённой страницы (Browser pane) в конце фазы.
- **Известные особенности:**
  - SSH к Hub рвётся — повторяй;
  - `go run ./cmd/deploy --ssh` печатает вывод дважды;
  - локальный python — `py -3`;
  - PROXY protocol на 443 включён, поэтому видны реальные IP клиентов.

## Критичность

- **Деньги (фазы A, W, R):** идемпотентность вебхуков, блокировки строк, суммы в копейках, тесты на гонки и повторы.

  - Если тестового магазина ЮKassa нет, проверь формирование запросов тестами.
  - Одну минимальную живую операцию — только с согласия владельца.
- **Ничего не помечай сделанным без двух доказательств:**
  - тесты: `go test ./cmd/... ./internal/...`, `npm test` в admin_web, `npm run build` для сайта и админки;
  - проверка на проде.
- **Ревью** — одно на фазу, по диапазону коммитов: агент code-reviewer, model sonnet. Исправления после ревью проверяешь сам.
- **Если пункт плана оказался неверным или вредным,** не делай его вслепую. Поправь план — коротко и с причиной — и скажи об этом в отчёте фазы.
