Ты пересобираешь сайт HiEarth (`site/`: маркетинг, вход, кабинет, оплата, кошелёк, рефералы, B2B) целиком на дизайн-систему **«Канон»** и выкатываешь его на прод. Владелец пишет по-русски — отвечай по-русски, коротко и по делу.

## Режим работы

- **Не останавливайся между этапами.** После каждого этапа — короткий отчёт в чат: что сделано, скриншоты, чем проверено. Затем сразу следующий этап.
- **Спрашивай владельца только** о решении, которого нет в спецификации, или о действии, которое может сделать только он.
- **Экономия токенов, как в CLAUDE.md.**
  - Пиши сам, inline.
  - Субагенты — только для широкого поиска и для одного ревью на этап (code-reviewer, model sonnet).
  - Не читай целиком большие файлы и `dist/`.

## Как работать (из HANDOFF.md, кратко)

1. **Фундамент:**
   - шрифты self-hosted: Manrope variable + JetBrains Mono 500/600/700; Lora и Raleway удалить;
   - `site/src/styles/hiearth.css`;
   - корень `<div className="he">`;
   - удалить Fireflies, AmbientFireflies, `.blob-*`, `.tree-sway`, `.glass*`, эко-тексты и старый `useReveal`. Анимации — только из `spec/04-motion.md`: одно оркестрованное появление на страницу (`.rise` + `--d`), ничего по скроллу.
2. **Общие компоненты** — по одному файлу на компонент, 1:1 с классами `hiearth.css`: Button, Field, Card, Badge, Alert, Toast, Dialog (никаких `window.confirm/alert/prompt`), Skeleton, EmptyState, CopyField, PlanCard, Steps, ListRow, SiteHeader, SiteFooter, AppShell и четыре из `react/`.
3. **Страницы — в порядке HANDOFF §6.** Каждая страница со всеми состояниями из таблицы «Page map» и из `spec/06–10`. Сюда же: кошелёк, рефералка, блок «Telegram» (WEB-прокси + классический) и подключение `/connect`.
4. **Мок API для разработки.** В `vite.config.js` нет прокси к API. Сделай мок только для разработки — фикстуры или Vite-middleware под `--mode mock`, в прод-сборку не попадает. С ним каждый экран открывается в каждом состоянии:
   - подписка активна / нет / закончилась;
   - на кошельке хватает / не хватает;
   - ошибки загрузки;
   - пустые списки.
5. **После каждой страницы:**
   - `cd site && npm run build`;
   - Browser pane (`preview_start`, `resize_window` 1440 и 390) — сравнение с артбордом;
   - `impeccable detect --json <изменённые файлы>`: движок `~/.claude/skills/impeccable/scripts/impeccable.cmd`, 0 предупреждений;
   - проверка STOP catches из CLAUDE.md: `grep` по сырым цветам, палитре Tailwind, `shadow-*`, «VPN», захардкоженным тарифам.
6. **Функциональность не теряется.** Каждая кнопка и форма делает то же, что до редизайна: тот же эндпоинт, те же поля, та же обработка ошибок, 401 → вход. Сверяйся с текущим кодом страницы.
   - Новый элемент или текст — сначала строка в `spec/`, потом код, в том же коммите (`spec/11-extending.md`).

## Этапы, ревью, деплой

**Этапы:**
- A — фундамент и компоненты;
- B — главная, помощь, документы, 404, письма, приглашение;
- C — регистрация и вход;
- D — кабинет, подключение, настройки;
- E — тарифы → оформление → оплата → результат, кошелёк, платежи, платёж;
- F — B2B (за `b2b_enabled`) и всё, что осталось.

**Ревью** — одно на этап, по диапазону коммитов. Исправления проверяешь сам.

**Деплой сайта** — после этапов B, D, E и F. Каждый раз:
1. Влей свежие ветки (см. выше).
2. Создай чистый worktree точного коммита. Скопируй `server/.env` из `C:\Users\alex\Documents\heyearthproject\server\.env`, его содержимое никогда не печатай.
3. В worktree: `cd site && npm ci`.
4. Из `server/backend` worktree: `go run quick_admin_web.go -site` — атомарная подмена, в конце HTTP 200.

**Если SSH к Hub не проходит** — `handshake failed: EOF` через Happ или порт 22 закрыт сетью — запусти `server/backend/scripts/prod/hubfwd.py`: способ запуска написан в шапке файла (прокси Happ или физическая сетевая карта). Правь `DEPLOY_HOST` и `DEPLOY_PORT` только в копии `.env` во временном worktree.

**Проверка на проде после деплоя:**
- публичные страницы на 1440 и 390, один скриншот на страницу;
- консоль без ошибок;
- шрифты Manrope и JetBrains Mono грузятся;
- старые светлячки исчезли.

Кабинет под реальным аккаунтом на проде не трогай и аккаунтов не создавай. Состояния кабинета проверяются на моке, а в финальном отчёте попроси владельца пройти кабинет своим аккаунтом.
