## Критично

1. **Пароль root от Hub лежал в публичном репозитории.** Был в `deploy_admin.py` и `deploy_site.py`, раньше ещё в `.claude/settings.local.json`. Из рабочего дерева удалён 12.11 (a9a722a), но в истории git он остаётся.
   - Входы по SSH за месяц — только с адресов владельца.
   - Вход по паролю для root включён (`PermitRootLogin yes`, `PasswordAuthentication yes`).
   - **Нужно (владелец):** сменить пароль root. Лучше перевести деплой на SSH-ключ и выключить вход по паролю.
2. **gRPC ClientApi доверяет `user_id` из запроса.** У `grpc.NewServer()` нет перехватчика. nginx пропускает `/heyearth.v1.ClientApi/` наружу. Зная `user_id`, можно:
   - получить ключи подключения (`GetConnectionBundle`);
   - увидеть платежи;
   - применить промокоды;
   - через `UpdateProfile` задать пароль аккаунту, у которого пароля нет, то есть захватить аккаунт.

   У gRPC `Login`/`Register` нет лимитов. Задача n1h0.
3. **Публичный `POST /api/v1/business/create-invoice` без авторизации** создаёт платёж в ЮKassa: можно спамить счетами. Форма счёта в админке не передаёт `tenant_id`, поэтому возможен дубль тенанта.
4. **На мобильном интернете VPN не работает с 7–12.11.** Решение готово и выкачено (резервный вход). Ждёт покупки VPS.
5. **Алерты никуда не уходят.** Telegram-бот и чат для алертов не заданы, за две недели 8 недоставленных тревог.
   - Висят ложные тревоги «Все exit-ноды недоступны» и «exit 2 недоступен» с 05.11, хотя exit работает: событие «восстановлено» не записывается (cudk.75).
   - Реальная тревога одна: запасной TCP-путь до exit.
