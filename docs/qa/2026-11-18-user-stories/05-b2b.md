## Находки

### S05-01 [P1] Приостановленная компания не возобновляется после пополнения, хотя экран и письмо обещают обратное
- Где: код (локально 9441d5c); экран мока `/business/dashboard` при `tenant=suspended`
- Шаги: компания в `suspended` пополняет кошелёк.
- Ожидалось: по тексту «Пополните — доступ восстановится после ежемесячного списания» (спека 10.4 п. 2'), а в письме — «после первого успешного платежа аккаунт автоматически возобновится».
- Получилось: `CreditTenantWalletTx` меняет статус только `inactive` -> `active`, `suspended` остаётся. `RunMonthlyTenantBilling` выбирает только `status='active'`, поэтому suspended-компанию не списывают и не возобновляют никогда. Выход один: админ меняет статус вручную.
- Доказательство: `internal/biz/payments.go:139` (`CASE WHEN status = 'inactive'`), `internal/biz/billing.go:37-41` (`WHERE status = 'active'`), `billing.go:116` (текст письма).
- Код: `server/backend/internal/biz/payments.go:135-141`, `server/backend/internal/biz/billing.go:37`
- Артефакт локального окружения? no (флаг на проде выключен, поэтому не P0)

### S05-02 [P1] Роль «Сотрудник» (роль по умолчанию в приглашении) после вступления попадает на экран ошибки
- Где: код; поток `/claim/<код>` -> `/business/dashboard?welcome=1`
- Шаги: админ создаёт приглашение с ролью по умолчанию «Сотрудник» (`user`), сотрудник нажимает «Присоединиться».
- Ожидалось: понятный экран для сотрудника (или не вести его в кабинет).
- Получилось: «Готово! Открываем кабинет компании…», затем `GET /business/me` отвечает 403 `no dashboard access for this role`, и кабинет показывает «Не удалось загрузить кабинет компании / Сервис временно недоступен. Попробуйте ещё раз через минуту». Кнопка «Повторить» бессмысленна. Мок расходится с API: в моке нет роли `user`, переключатель `b2b` её не предлагает.
- Доказательство: `b2b_handlers.go` `handleBusinessMe` (`role == "user"` -> 403); `BusinessDashboardPage.jsx` `load()` ловит всё, кроме `no B2B membership`, в `loadErr`.
- Код: `server/backend/cmd/api/b2b_handlers.go:148`, `site/src/pages/BusinessDashboardPage.jsx:84-91`, `site/src/pages/ClaimCodePage.jsx:22`
- Артефакт локального окружения? no

### S05-03 [P2] «Мест не осталось — новые сотрудники не смогут присоединиться» не соответствует API

### S05-05 [P2] Что приостановка (`suspended`) блокирует — нигде не блокирует, но экран говорит «доступ»

### S05-07 [P3] Мелочи кабинета
- «тариф «basic»» — сырой слог `tenants.plan` латиницей в строке «Следующее списание» (спека: «<план>»).
- «Следующее списание — 1 декабря…» показывается и для `inactive`, хотя неактивный не списывается.
- Для billing/viewer метка «(вы)» не появляется: API отдаёт им укороченный `user_id` (`3f2b…9b0c`), а страница сравнивает с полным ID профиля. Мок отдаёт полный ID — мок расходится с API.
- Шаг «Готово» регистрации для уже вошедшего пользователя всё равно пишет «Зарегистрируйтесь на сайте, затем откройте эту ссылку».
- Спека 10.5 для гостя пишет `/login?next=`, код использует `?redirect=` (как в 10.2); обновить спеку.
- Авторизованные `/business/me`, `/invite`, `/topup-init` не проверяют `b2b_enabled`; при выключенном флаге существующие участники всё ещё получают API (сайт при этом показывает 404).

### Мок расходится с API
- Нет роли `user` (в API: 403 на `/business/me`).
- Мок при `b2b=off` отвечает 404 `no B2B membership` на `/business/*`; реальный API — 404 только у public create-tenant/create-invoice, остальные работают независимо от флага.
- Мок создания счёта отдаёт только `payment_id`, как и API; поле `invoice_id` не моделируется, поэтому проблему S05-04 мок не показывает.
- Мок не хранит состояние: после смены роли/удаления сотрудника повторная загрузка возвращает прежний список; ошибки «последний админ» (409) не воспроизводятся.
- Мок отдаёт `invoices: null` при пустой истории, реальный API тоже (`var out []b2bInvoice`); страница это обрабатывает.
- Мок не проверяет сумму больше 1 000 000 ₽ и лимит 429 у счёта.

## Что работает
- Флаг off на проде и локально: все business-маршруты и `/claim/*` дают обычную 404, ссылок «Для бизнеса» в шапке и футере нет, `/business/dashboard` для гостя тоже 404 (B2BOnly раньше RequireAuth).

- Лендинг: тексты и цены 250 / 1 000 / +100 по спеке, пример панели помечен «данные условные».
- Регистрация компании: пустые поля, плохой email, пересчёт оценки (минимум 1 сотрудник), «Свои» показывает поле серверов, шаг «Готово» со ссылкой и кнопкой по состоянию входа.
- Счёт: ошибки ИНН (10/12) и «Минимум 100 ₽», успешный результат со ссылкой и «Перейти к оплате», «Вернуться».

- 390 px: без горизонтальной прокрутки.
- Консоль: ошибок нет; на странице кабинета правило одной primary-кнопки соблюдено (в диалогах — по одной).
