## Шаги
1. `/register` → «Получить HiEarth ID»: показан «номерок» (карточка с ID), блок с ID, кнопки копирования и «Скачать файл с ID», текст «Сохраните его: восстановить нельзя», чекбокс «Я сохранил свой HiEarth ID…» блокирует «Продолжить в кабинет».
2. Там же форма «Логин и пароль»: пароль `abc` → «Пароль должен быть не менее 4 символов»; `qapass-one` → «Изменения сохранены», «Логин … сохранён». Перезагрузка страницы на шаге «ID выдан» сохраняет ID (sessionStorage `he_pending_registration`).
3. Вход по ID: неверный пароль даёт понятную ошибку с подсказкой про раскладку и поддержку. Правильный пароль, вход по логину и по ID — 200, редирект в кабинет. (Разбор текстов ошибок входа — в Beads, метка security.)
4. Две curl-сессии (`POST /api/v1/auth/login`, токены c1, c2) → оба 200 на `/api/v1/user/profile`. В `/settings` сменил пароль: сначала неверный текущий → «Неверный текущий пароль» под полем; затем верный. После смены: c1 → 401, c2 → 401, сессия браузера → 200. В БД `user_sessions` осталась 1 строка (было 5).
5. Выход: `/settings` → «Выйти из аккаунта» → диалог «Точно выйти?» (показывает усечённый ID и логин) → «Выйти». Токен из браузера после выхода: `/user/profile` → 401; повторный `POST /auth/logout` → 204 (идемпотентно).
6. «Войти через браузер»: это кнопка в `/tg` (Mini App, `TelegramEntryPage.jsx:235`). Открывает во внешнем браузере `/telegram/connect` (`TelegramConnectPage.jsx`), где нужна сессия сайта, и привязывает Telegram через бота (`POST /api/v1/user/telegram/link`). Магических токенов (`/m/:token`, `auth_magic_tokens`) в сайте на 9441d5c нет, `/m/badtoken` → 404 (в `main.jsx` такого маршрута нет). Проверено без Telegram:
   - `/telegram/connect` без входа → `/login?redirect=%2Ftelegram%2Fconnect`, после входа возвращает на страницу;
   - со входом: «Подключить Telegram», «Аккаунт: a693…6c1b»;
   - нажатие → локально ожидаемо «Не удалось подключить. Бот HiEarth пока не подключён — попробуйте позже» (503);

   Остальное: только владелец (Telegram).
7. Прод `https://hiearth.ru/login`: заголовок, поля, подсказки и тексты совпадают с локальным (сверено по тексту `main`), бандл `index-C7sUfWsr.js`, ничего не отправлялось.

### S03-01 [P2] Нет экрана «Устройства / сессии»: нельзя увидеть и закрыть чужую сессию
- Где: local http://localhost:5174/settings (и по коду `site/src`)
- Шаги: поискать список сессий/устройств в кабинете (grep `site/src` по «сесси/устройств/sessions») и маршрут в API.
- Ожидалось: список активных сессий и кнопка «закрыть» (по условию шага 4). Если HiEarth ID утёк, человек должен уметь закрыть чужой вход.

- Примечание: шаги «ревок своей сессии» и «ревок curl-сессии кнопкой» не проверялись именно из-за этого.

## Что работает
- Регистрация одним кликом выдаёт ID; ID показан крупно («номерок»), есть копирование, скачивание файла и предупреждение «восстановить нельзя»; без галочки «сохранил» в кабинет не пустит.
- Шаг «ID выдан» переживает перезагрузку страницы (ID не теряется до подтверждения).
- Установка логина и пароля на шаге регистрации; валидация длины пароля с понятным текстом; индикатор силы.
- Вход по ID и по логину.
- Смена пароля: ошибка неверного текущего пароля под полем; после смены остальные сессии (curl) закрыты (401), сессия вызывающего жива (200), в `user_sessions` осталась одна строка.
- Выход: диалог подтверждения, токен убит на сервере (401 при повторе), повторный `logout` идемпотентен (204).
- `/telegram/connect`: редирект на вход с возвратом; страница рендерится; ошибка без бота понятная.
- `/tg` в обычном браузере: понятная заглушка с кнопкой «Войти на сайте».
- Прод `https://hiearth.ru/login` совпадает с локальной страницей по тексту; на проде 401 на `/api/v1/user/profile` без токена.
