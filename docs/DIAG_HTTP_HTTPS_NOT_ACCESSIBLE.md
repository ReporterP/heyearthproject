# Почему heyearth.ru не открывается по HTTP/HTTPS без VPN

Пинг и SSH работают, а браузер по http/https — нет. Ниже проверки по шагам.

## 1. Что проверить у себя (без VPN)

В терминале (PowerShell или WSL):

```bash
# Есть ли вообще TCP до портов 80 и 443?
nc -vz heyearth.ru 80
nc -vz heyearth.ru 443
# или: timeout 5 bash -c 'echo >/dev/tcp/heyearth.ru/80' && echo "80 open" || echo "80 closed/filtered"
```

```bash
# Что именно возвращает HTTP?
curl -v --connect-timeout 10 http://heyearth.ru
curl -v --connect-timeout 10 https://heyearth.ru
```

Запомни результат:
- **Connection refused** — до сервера доходим, но на 80/443 никто не слушает или фаервол режет.
- **Timeout / No route** — пакеты до портов 80/443 не доходят (часто блокировка у провайдера).
- **HTTP 200 или 301** — по факту всё работает, тогда проблема в браузере/DNS.

---

## 2. На сервере (по SSH)

### 2.1 Слушает ли nginx 80/443 снаружи

```bash
sudo ss -tlnp | grep -E ':80|:443'
# или
sudo netstat -tlnp | grep -E ':80|:443'
```

Ожидаем что-то вроде:
- `0.0.0.0:80` и `0.0.0.0:443` — норма (приём с любых интерфейсов).
- `127.0.0.1:80` — только localhost; с интернета не заработает, нужно в конфиге nginx поменять на `listen 80;` (без привязки к 127.0.0.1).

### 2.2 Фаервол (ufw / iptables)

```bash
sudo ufw status
```

Если ufw включён, должны быть разрешены 80 и 443:

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw reload
```

Проверка iptables:

```bash
sudo iptables -L INPUT -n -v | head -30
```

Правила не должны дропать 80/443 для твоего интерфейса (eth0/ens и т.п.).

### 2.3 Nginx отвечает ли локально

```bash
curl -I http://127.0.0.1
curl -I -k https://127.0.0.1
```

Если здесь 200/301, а с твоего ПК без VPN — нет, значит блокировка не на сервере, а по пути (часто провайдер).

### 2.4 Конфиг nginx: listen

```bash
grep -r "listen" /etc/nginx/
```

Для доступа с интернета нужно:
- `listen 80;` или `listen [::]:80;`
- не только `listen 127.0.0.1:80;`

---

## 3. Если с сервера всё ок, а с дома без VPN — нет

Типично это **блокировка у провайдера** (РКН, DPI и т.п.): режут именно 80/443 до твоего IP или домена, а ICMP и SSH не трогают.

Что можно сделать:

1. **Проверить с другого канала** — мобильный интернет (раздать с телефона) или другой провайдер. Если там http/https открываются — точно блокировка у основного провайдера.
2. **Использовать CDN перед сервером** — отдать сайт в Cloudflare (или другой CDN): домен указывает на CDN, CDN ходит на твой сервер по 80/443. Запросы пользователей идут к IP CDN; часто до CDN блокировок меньше. Нужно будет в DNS прописать A-записи на Cloudflare и включить proxy (оранжевое облако).
3. **Оставить доступ по VPN** — для себя и тех, у кого уже стоит клиент, ничего не менять.

---

## 4. Краткий чеклист

| Где | Действие |
|-----|----------|
| У себя без VPN | `nc -vz heyearth.ru 80`, `curl -v http://heyearth.ru` — смотреть ошибку |
| Сервер | `ss -tlnp \| grep 80` — слушает ли 0.0.0.0:80 |
| Сервер | `ufw status`, при необходимости `ufw allow 80/tcp` и 443 |
| Сервер | `curl -I http://127.0.0.1` — отвечает ли nginx локально |
| Nginx | В конфиге `listen 80;` (не только 127.0.0.1) |
| Если сервер ок | Другой канал / CDN / доступ по VPN |

После того как выполнишь шаги 1 и 2, по выводу команд можно точно сказать: проблема в сервере/фаерволе или в блокировке по пути (провайдер).
