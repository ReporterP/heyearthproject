# Изменение путей в подписке: канарейка, поточечная проверка, срочная доставка

Правило появилось после инцидента 20.11.2026 (`docs/incidents/2026-11-20.md`). Коммит `1a92c81` («⚡ Авто» только через входы) ушёл всем пользователям Happ сразу. Вход 6 проходил одиночные пробы, хотя 40–60 % его 5-tuple были мёртвыми. Клиенты на Wi‑Fi потеряли связь. Откат дошёл до них только через интервал обновления подписки: на проде он был 12 часов.

## Что считается изменением путей

Всё, что меняет, через какой адрес, порт или протокол пойдёт трафик пользователя:

- строки и балансировщики JSON-подписки (`cmd/api/subscription_json.go`: пути «⚡ Авто» и Бамбука, цены, пробы);
- URI-строки (`cmd/api/client_api.go`: основные, «· резерв», «· напрямую»);
- режим входов (`hub` / `relay` / `auto`), цель режима `relay`;
- новый вход в ротации, вход, возвращённый в ротацию, смена его адреса;
- адрес хаба (мастер «Хаб → Адрес», `docs/runbooks/hub-address-change.md`).

## 1. Канарейка: сначала тестовый пользователь, сутки, потом все

| Что меняем | Как включить только для одного пользователя |
|---|---|
| Форма JSON-подписки («⚡ Авто», Бамбук) | «Входы» → «Авто»: режим `test` и тестовый пользователь (`sub_auto_mode=test`, `sub_auto_test_user`). Все остальные получают прежние URI |
| Переключение на резервный вход | «Входы» → «Тестовый пользователь»: `entry_failover_test_user` видит подписку как при аварии |
| Прямые соединения JSON-подписки «по имени» (`routeOnly:false`, `IPOnDemand`, direct IPv4 первым) | `PUT /api/admin/entries/settings {"direct_by_name":"test"}` → `sub_direct_by_name=test`: только `sub_auto_test_user`; `on` — все, `off` — как раньше. Кнопки в админке пока нет |
| Новая логика в коде без готового переключателя | Сначала добавить переключатель на тестового пользователя, потом выкатывать. Код, который меняет пути сразу всем, не мержить |

Порядок:

1. Выкатить с переключателем на тестового пользователя. Обновить подписку на его телефоне.
2. 24 часа проверять у тестового пользователя на мобильной сети и на Wi‑Fi: страницы, видео, звонки, мессенджеры. Проверять тот путь, который реально выбрал Happ.
3. Перед включением для всех — поточечная проверка (раздел 2) каждого нового обязательного пути.
4. Включить для всех **вместе со срочным обновлением** (раздел 3). Тогда, если всё же сломается, откат дойдёт до всех за час.

## 2. Поточечная проверка пути, прежде чем он станет обязательным

Одна проба ничего не доказывает: битый канал у провайдера может терять только часть 5-tuple. Ping и маленькие ответы при этом проходят.

```bash
cd server/backend
go run ./cmd/deploy --path-matrix <ID входа>
```

Что делает проверка (только читает, на хабе — отвязанное задание, лог `/var/log/heyearth-path-matrix-<ID>.log`):

| Группа | Что | Порог |
|---|---|---|
| хаб → вход | TCP к :443 и :2443 входа с 50 разных source port | ≥ 95 % |
| вход → хаб | TCP к :8447, :443, :2443 хаба с 50 разных source port | ≥ 95 % |
| через выход | TLS с SNI Reality через выход за рубежом на :443 и :2443 входа — то, что видит пользователь | ≥ 99 % |

Последняя строка — `PATH_MATRIX verdict=PASS|FAIL`. С FAIL путь обязательным не делать.

Для nginx stream входа отдельно: `go run ./cmd/deploy --relay-stream <ID> --relay-stream-check`. Это 40 TLS-рукопожатий через :443 самого входа до хаба, без изменений.

## 3. Срочная доставка изменения

Подписка доходит до приложения только при его следующем обновлении. Что есть:

| Рычаг | Где | Что даёт |
|---|---|---|
| Базовый интервал | «Входы» → «Как часто приложения обновляют подписку», `subscription_update_interval_hours`. Код по умолчанию — 4 ч | Худшая задержка любой правки. 12 ч — слишком долго |
| Срочное обновление | «Входы» → «Срочное обновление» → «Включить на 24 ч» (`subscription_urgent_until`) | Каждый, кто обновил подписку, дальше обновляется раз в час. Все последующие правки внутри инцидента доходят за час |
| Попросить обновить вручную | Поддержка, бот, канал | Мгновенно, но только у тех, кто прочтёт |

Во время аварии входа интервал и так 1 час (режим `auto` при активном переключении).

Порядок при поломке, задевшей пользователей:

1. Включить «Срочное обновление».
2. Откатить или исправить.
3. Тем, кто обновлял подписку в плохое окно (`users.subscription_fetched_at`), написать «обновите подписку в Happ».

## 4. Проверка после включения для всех

- Первые часы: `alert_events`, `traffic_stats` по 15 минут (нет ли провала у части пользователей), лог nginx входов (`upstream timed out`).
- Есть подозрение на конкретного клиента — сверить адрес из логов входа с `access.log` хаба и журналом `hysteria2-server` на хабе. Наружу адреса не уносить. Пример — в отчёте об инциденте 20.11.
