# Если нас DDoS-ят (и как устроена защита)

Защита по слоям, от сети к приложению. Всё ставится кодом: `go run ./cmd/deploy --setup-hardening` (Hub; также последним шагом `--setup-ops`), `--harden-nodes [--node-upgrade]` (exit и входы). Изменения sshd и файрвола откатываются сами через 5 минут, если после них не удался новый вход по SSH.

### Режим таблицы `heyearth_ddos`: наблюдение → защита

С 18.11 таблица работает в режиме **observe**: считает и пишет в журнал ядра пример адресов сверх лимита (`he-ddos-*`), но ничего не режет (кроме посторонних на `:8447`). Включать **enforce** — после вечернего пика, когда видно, что обычные пользователи до лимитов не доходят:

```bash
go run ./cmd/deploy --ssh 'nft list counters table inet heyearth_ddos; journalctl -k --since "-24h" | grep -c he-ddos'
```

- `over_tcp_lo` / `over_udp_lo` — сколько раз обычный трафик превышал **низкие** пороги (30 новых TCP/с, 8 000 UDP пак/с) — для калибровки;
- `over_tcp` / `over_udp` / `over_ssh` — превышения **рабочих** порогов. Если за сутки без атаки они 0 (или единицы от сканеров) — можно включать:

```bash
go run ./cmd/deploy --setup-hardening --ddos-mode enforce
```

Откат в наблюдение — тот же флаг с `observe`. Пороги меняются в коде (`defaultDDoSLimits`, `cmd/deploy/ops_hardening.go`).

## Что делать при атаке

1. **Понять, что падает.** `go run ./cmd/deploy --status`; алерт «Похоже на атаку» перечисляет признаки. Снаружи: открывается ли сайт, работает ли Happ (Wi‑Fi и мобильный).
2. **Состояние Hub:**

   ```bash
   go run ./cmd/deploy --ssh 'uptime; sysctl -n net.netfilter.nf_conntrack_count net.netfilter.nf_conntrack_max; ss -s | head -3; nft list counters table inet heyearth_ddos | grep -B1 packets; fail2ban-client status heyearth-nginx-scan | tail -2'
   ```

   Топ адресов по соединениям (без вывода самих адресов в чат — смотреть на сервере):

   ```bash
   ss -Htn state established '( sport = :443 )' | awk '{print $4}' | sed -E 's/:[0-9]+$//' | sort | uniq -c | sort -rn | head
   ```

3. **Флуд с отдельных адресов** (счётчики `over_*` растут): включить `--ddos-mode enforce`, если ещё не включён. Точечно забанить адрес: `fail2ban-client set heyearth-nginx-scan banip <адрес>` (бан на 80/443).
4. **Объёмная атака на канал** (Hub недоступен целиком, счётчики не растут — пакеты не доходят): это уровень провайдера.
   - Написать в поддержку VDSina (текст — в отчёте владельцу), попросить включить фильтрацию / прислать данные об атаке.
   - Пользователи Happ в режиме «Авто» сами уйдут на входы: проверить в админке «Серверы → Входы в РФ» режим и состояние входов; при необходимости — «Всех через вход» (`PUT /api/admin/entries/mode`, режим relay).
   - Сайт и админка в это время недоступны через Hub; если подключён DDoS-прокси (DDoS-Guard/StormWall/Yandex) — переключить A-записи сайта на него.
5. **Атака на API** (много 429/503 в журнале nginx, отказы `loadShed`): лимиты nginx уже режут по адресу; посмотреть `journalctl -u heyearth-api | grep -c "too many"` и топ путей в `access.log`; при атаке на один путь — временно закрыть его в nginx (`location = /путь { return 444; }` в `conf.d/heyearth.conf`, `nginx -t && systemctl reload nginx`), потом вернуть генератором (`deploy --nginx`).
6. **SSH недоступен** (переполнен перебором): консоль VNC в панели VDSina; там `fail2ban-client status sshd`, `systemctl restart ssh`.
7. После атаки — записать, что было, в Beads и сюда.

## Кому писать

- VDSina (Hub): поддержка в личном кабинете / тикет — «защита от DDoS, данные об атаке, фильтрация».
- Timeweb (входы, exit): тикет в панели.
- DDoS-прокси (если подключён) — его поддержка.

## Админка: 2FA

Включается в «Настройки → Аккаунт → Двухфакторный вход» (QR для Google Authenticator / Aegis / 2FAS). После 5 неудачных попыток (пароль или код) вход блокируется на 15 минут. **Потерян телефон** — выключить 2FA на сервере:

```bash
go run ./cmd/deploy --ssh "sudo -u postgres psql heyearth -c \"UPDATE admin_users SET totp_enabled = FALSE, totp_secret_enc = NULL, totp_pending_enc = NULL, failed_logins = 0, locked_until = NULL WHERE username = '<логин>'\""
```

## Проверка после любых изменений

- подписка не изменилась: `scripts/prod/snap_subscriptions.sh` до и после;
- Бамбук — с exit: `scripts/prod/bamboo_from_exit.sh` (с Hub проверять нельзя);
- сайт, кабинет, админка открываются; вебхук ЮKassa проходит; боты отвечают.
