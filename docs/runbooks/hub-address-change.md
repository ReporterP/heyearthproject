# Смена адреса хаба

Мастер: админка → «Серверы» → вкладка «Hub» → карточка «Адрес хаба». Право — `hub.address`.
Дизайн: `docs/superpowers/specs/2026-11-20-hub-address-change-design.md`.

Адреса в этом документе — примеры из RFC 5737. Настоящие адреса хранятся в админке и `server/.env`.

## Перед покупкой адреса

- Закажите у VDSina **дополнительный IP на этот же VPS**. Новый VPS — это переезд хаба, мастер его не делает.
- Мобильные операторы режут **подсеть VDSina целиком**. Поэтому просите адрес из другого диапазона. В шаге 1 мастер показывает /24 нового и текущего адреса, а шаг 2 проверяет новый адрес с телефона до любых переключений.
- Если адрес уже поднят на интерфейсе (так бывает с cloud-init), мастер его не трогает и при отмене не снимает.

## Шаги

1. **Добавить адрес.**
   - Делает `ip addr add <new>/32` на интерфейсе маршрута по умолчанию и добавляет одну строку в тот файл `/etc/netplan/*.yaml`, где перечислены адреса интерфейса.
   - Копия файла сохраняется как `<файл>.bak-hubaddr-<id>`. Выполняется только `netplan generate`, `apply` — никогда.
   - Шаг откажется и ничего не тронет, если разметка непривычная. Тогда правьте файл руками и запустите шаг снова:
     - список адресов в одну строку;
     - адреса интерфейса заданы в нескольких файлах;
     - в том же файле нет ровно одного `routes: [{to: default, via: …}]` (например, старый `gateway4:`): к нему на шаге 5 добавится `from:`;
     - файл `50-cloud-init.yaml`, а сеть cloud-init не отключена: после перезагрузки cloud-init перепишет файл. Отключите её в `/etc/cloud/cloud.cfg.d/99-disable-network-config.cfg`, строкой `network: {config: disabled}`.
2. **Проверить.**
   - Исходящие с нового адреса и для сравнения с текущего: по 24 соединения к каждому входу, выходу, Let's Encrypt, GitHub и ЮKassa.
   - Почта (вход SMTP) и ЮKassa (`GET /v3/me`) с нового адреса.
   - Из-за рубежа через выход: сайт, Берёза и Дуб.
   - Из РФ: с каждого входа скачиваются 256 КБ.
   - С телефона: выключите Wi-Fi и откройте ссылку или QR-код. Кнопка «Сравнить с текущим» покажет, режет ли оператор подсеть.
   - Проверку с телефона можно пропустить только явно, это записывается в журнал аудита.
3. **Подготовить узлы.**
   - Переустанавливаются все выходы и входы в сети: в разрешения попадает новый адрес, а трафик пока идёт по-старому.
   - Там, где SSH открыт только для адресов хаба, добавляется то же правило для нового адреса.
   - Узел не в сети блокирует шаг. Его можно исключить, но после переключения хаб потеряет с ним связь, пока узел не переустановят.
4. **DNS.**
   - В Cloudflare поменяйте A-записи, которые мастер показал на текущем адресе (обычно `hiearth.ru` и `admin`). Оранжевое облако не включайте.
   - `go` и `tg` смотрят на вход, их не трогайте.
   - Шаг пройдёт, когда 1.1.1.1, 8.8.8.8 и 77.88.8.8 начнут отдавать новый адрес, а сертификат на нём совпадёт с именами.
5. **Переключить.**
   - Мастер записывает скрипт отката в `/opt/heyearth/state/hubaddr/<id>-revert.sh` и **заранее** взводит таймер `heyearth-hubaddr-revert-<id>`.
   - Затем меняет источник маршрута (пока только в памяти, без netplan), перезапускает туннели к выходам и переводит `main_server_host`.
   - Дальше по очереди перенастраивает входы. Бамбук прерывается на несколько минут.
   - Пока входы перенастраиваются, таймер продлевается, но не дольше 40 минут. Потом у вас 10 минут, чтобы нажать «Подтвердить».
   - Подтверждение снимает таймер и записывает в netplan `from: <new>`.
6. **Переходный период.**
   - Подписки обновляются раз в час. Карточка показывает, сколько активных пользователей уже обновили подписку (N из M), и число новых соединений в минуту на старый адрес.
7. **Вывести старый адрес.**
   - Шаг открывается через 72 часа, если обновили не меньше 90 % и на старый адрес приходит меньше одного соединения в минуту. Раньше — только через «Вывести несмотря на…».
   - Адрес снимается с интерфейса и из netplan под таймером возврата. Адрес, через который идёт шлюз, никогда не снимается.

## Откат

- **Кнопкой.** «Вернуть как было» доступна в шагах 5 и 6.
- **Сам.** Откат происходит без вас, если:
  - вы не подтвердили переключение до конца отсчёта;
  - хаб перезагрузился посреди шага 5 (netplan ещё со старым источником);
  - таймер исчез.

  Наблюдатель API раз в 30 секунд доводит откат: возвращает настройки и перенастраивает входы обратно. Неудачные попытки он повторяет раз в 5 минут и один раз шлёт алерт в бот тревог.
- **Отмена до шага 5.** «Отменить смену» снимает добавленный мастером адрес и возвращает netplan. DNS вы возвращаете сами.

## Если админка недоступна (VNC у хостера)

Подставьте свои адреса, `<id>` — номер смены.

```bash
# вернуть источник маршрута и всё, что делает откат (маршрут, main_server_host, туннели)
sh /opt/heyearth/state/hubaddr/<id>-revert.sh
# или только маршрут
ip route replace default via 203.0.113.1 dev ens3 src 192.0.2.10
# запустить откат по таймеру сразу
systemctl start heyearth-hubaddr-revert-<id>.service
# посмотреть, взведён ли таймер
systemctl list-timers 'heyearth-hubaddr-*'
```

## После завершения

- Поменяйте `DEPLOY_HOST` в `server/.env`. Ключ хоста остаётся прежним.
- Если адрес снят с хаба, откажитесь от него у VDSina.
- Переустановите выходы и входы в «Серверах», чтобы убрать старый адрес из их разрешений. Лишнее разрешение безвредно, так что это можно сделать позже.
