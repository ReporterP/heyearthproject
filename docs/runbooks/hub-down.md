# Хаб недоступен, пульта нет

Когда пришло сообщение от внешнего сторожа («пульс хаба пропал») или от сторожа на выходе («Хаб недоступен снаружи»), админка, скорее всего, тоже не открывается: она живёт на хабе. Ниже — пять шагов без неё. Адресов в документе нет: они в `server/.env` и в панели провайдера.

Кто прислал сообщение — уже подсказка:

| Что пришло | Что это значит |
|---|---|
| Пропал пульс хаба и пульс API, сторожа на выходах молчат | Хаб не может выйти наружу, но снаружи открывается. Проверить исходящую сеть хаба |
| Пропал только пульс API | Упал или завис `heyearth-api`. Сайт и кабинет лежат, уже открытые соединения VPN живы |
| Сторожа на выходах: «Хаб недоступен снаружи», пульсы идут | Хаб жив, но его адрес не открывается из-за рубежа: фильтрация адреса или nginx |
| Всё сразу | Хаб выключен, завис или потерял сеть |

## 1. Панель провайдера

Открыть панель хостинга хаба. Сервер запущен? Есть ли уведомления о работах, блокировке, неоплате? Если сервер выключен — включить. Если завис (консоль не отвечает) — перезагрузить из панели: это **К3**, но хаб и так никого не обслуживает.

## 2. SSH

С компьютера владельца прямое соединение на порт 22 может не проходить (см. `CLAUDE.md`, «SSH from the owner's PC»):

```bash
python waitfwd.py 2224 <адрес хаба>:22 <адрес сетевой карты>
# в другом окне
cd server/backend
DEPLOY_HOST=127.0.0.1 DEPLOY_PORT=2224 go run ./cmd/deploy --ssh 'uptime'
```

Не открывается и так — консоль в панели провайдера (VNC).

## 3. Четыре сервиса

```bash
go run ./cmd/deploy --ssh 'systemctl status xray hysteria2-server nginx heyearth-api --no-pager | grep -E "●|Active:"'
```

| Не работает | Что делать | Класс |
|---|---|---|
| `heyearth-api` | `journalctl -u heyearth-api -n 50`; затем `systemctl restart heyearth-api` | К1 |
| `nginx` | `nginx -t`; затем `systemctl start nginx` | сервис уже лежит |
| `xray` | `journalctl -u xray -n 30`; `systemctl start xray`. Конфиг пишет API: если API жив, он перезапишет его сам | сервис уже лежит |
| `hysteria2-server` | `journalctl -u hysteria2-server -n 30`; `systemctl start hysteria2-server` | сервис уже лежит |

Перезапускать то, что **работает**, не нужно: это рвёт соединения живых пользователей (К2, К3) и почти никогда не лечит.

## 4. Общая картина

```bash
go run ./cmd/deploy --status
```

Смотреть: все ли сервисы `active`, отвечает ли `curl https://<сайт>/api/v1/health`, здоровы ли туннели к выходам, сколько места на диске. Если диск полон — `journalctl --vacuum-size=1G` и повторить шаг 3.

## 5. Адрес отфильтрован

Признаки: хаб жив, сервисы работают, изнутри всё отвечает, а снаружи адрес не открывается — сторожа на выходах пишут, пульсы идут. Это случай из инцидентов 10.10 и 20.11: провайдер или транзит режет адрес.

- Проверить с другого адреса хаба, если он есть: открывается ли сайт по нему.
- Сменить адрес — только мастером «Серверы → Hub → Адрес хаба» (`docs/runbooks/hub-address-change.md`): от адреса зависят входы, выходы и Бамбук. Смена адреса — **К3**.
- Пока адрес не сменён, мобильные пользователи идут через резервные входы; проверить, что вход в ротации жив (`go run ./cmd/deploy --path-matrix <id входа>`).

## После

- В ленте пульта («Операции») появятся записи о загрузке хаба и старте сборки; сторож на выходе сам напишет «Хаб снова доступен».
- Записать инцидент в `docs/incidents/REGISTRY.md`: что пришло первым, сколько минут до сообщения, что помогло.

## Учения

Раз в квартал: остановить пульс на пять минут и убедиться, что внешний сторож прислал тревогу.

```bash
go run ./cmd/deploy --ssh 'systemctl stop heyearth-pulse.timer'
# ждать сообщения, не больше 5 минут
go run ./cmd/deploy --ssh 'systemctl start heyearth-pulse.timer'
```

Это **К0**: пульс — отдельный таймер, на трафик не влияет.
