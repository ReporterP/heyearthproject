# Runbook: GRE-туннель вход ↔ хаб

Адреса — RFC 5737: хаб `203.0.113.10`, вход 6 `198.51.100.42`. Реальные адреса есть только в `server/.env` и в админке.

## Зачем

Инцидент 20.11.2026 (`docs/incidents/2026-11-20.md`): на транзите между провайдерами битый член ECMP/LAG терял все пакеты части 5-tuple в сторону входа. У GRE нет портов: все потоки входа идут внутри одной пары внешних адресов. Путь либо работает целиком, либо целиком лежит, и тогда монитор уводит вход из подписки.

## Как устроено

| Что | Хаб | Вход |
|---|---|---|
| Интерфейс | `he-r<id>` | `he-hub` |
| Юнит | `heyearth-tunnel-r<id>.service` | `heyearth-tunnel.service` |
| Адрес (пул `10.77.0.0/16`, по `/30` на вход) | `10.77.0.0 + 4·id + 1` | `+2` |
| MTU | 1476 | 1476 |

Для входа 6 это хаб `10.77.0.25`, вход `10.77.0.26`.

- **Вход, nft (`/etc/heyearth/relay.nft`).** DNAT TCP 2443 → `хаб_туннель:2443`, UDP 30000–65000 → `хаб_туннель:50443`. Masquerade в туннель, MSS clamp на SYN в `he-hub`.
- **Вход, nginx (`/etc/nginx/nginx.conf`).** 443/80: 2 попытки на `хаб_туннель`, затем 6 попыток на публичный адрес хаба (`backup`). Туннель лёг — сайт и Берёза живут, Дуб и Бамбук нет.
- **Хаб, ufw.** `allow proto gre from <вход> to <хаб>` с комментарием `heyearth-tunnel-<id>`.
- **Хаб, доверие PROXY.** В `/etc/nginx/heyearth-relays/<вход>.conf` две строки `set_real_ip_from`: публичный адрес входа и адрес туннеля.
- **Хаб, allow-скрипт.** `heyearth-ddos-allow.sh` кладёт в `allow4` и в доверенный список nginx адреса из поля `peer` у интерфейсов `he-r*`.
- **Хаб, Hysteria.** Отвечает с адреса маршрута. Маршрут к адресу входа идёт через `he-r<id>` с `src` адреса туннеля хаба — это ровно тот адрес, на который вход делал DNAT.
- **Монитор входов.** Проверяет TLS к :443 и к :2443 через выход, у :2443 одна повторная попытка. Туннель лёг → :2443 не отвечает → через 3 проверки вход `unhealthy`, его строки уходят из подписки, приходит алерт `relay-<id>-unreachable-external`.

## Перевести вход на туннель без возврата в ротацию

```bash
cd server/backend
go run ./cmd/deploy --relay-tunnel 6 --relay-tunnel-check   # только замер и проверка адресов
go run ./cmd/deploy --relay-tunnel 6                        # изменение
```

Оба запуска идут отвязанно на хабе: логи `/var/log/heyearth-relay-tunnel-check-6.log` и `/var/log/heyearth-relay-tunnel-6.log`. `lifecycle` входа не меняется.

Что делает изменение:
1. **Хаб.** Ставит предохранитель `heyearth-relay-tunnel-hub-guard-6` на 25 минут: он вернёт прежние юнит, доверие, allow-скрипт и правило ufw. Затем поднимает туннель и сверяет маршрут по умолчанию, источник и адреса хаба до и после.
2. **Вход.** Ставит свой предохранитель `heyearth-relay-tunnel-guard` на 15 минут. Затем поднимает туннель, проверяет ping и TCP :8447 через него, переключает nft и nginx, обновляет jail fail2ban (адрес хаба).
3. **Замер «после» с выхода.** 100 TLS к :2443 и 100 проб Бамбука, с других source port, чем «до».
4. **Решение.** TCP и UDP ≥ 99 %, собственный :443 входа ≥ 95 % и не хуже, чем до → оба конца подтверждены: юниты включены, предохранители сняты. Иначе оба конца сразу откатываются.

Повторный провижн входа из админки после этого ничего не меняет: файлы те же, что пишет рецепт.

## Туннель — выбор владельца (с 2026-11-21)

Туннель ставится только входу с флагом `servers.relay_tunnel` (миграция 000096, по умолчанию выключен; входу 6 миграция его включила). Без флага рецепт идёт путём до туннеля: nft DNAT и nginx на публичный адрес хаба, ретраи nginx остаются.

- **Новый вход.** Галочка «Туннель до Hub» в мастере, по умолчанию снята.
- **Проверить заранее.** «Входы» → «Управление» → «Проверить туннель» (задача `tunnelcheck`, только для входа без туннеля). Поднимает оба конца, предохранитель на хабе не снимается: туннель исчезнет не позже чем через 10 мин, даже если API упадёт. Замер: TCP с входа на `хаб_туннель:8447`, `:443`, `:2443` с 50 source port, порог 95 %. Затем оба конца снимаются. nft и nginx входа не трогаются, пользователи ничего не замечают. Единственное, что остаётся на входе, — правило ufw `allow proto gre from <хаб>`: оно безвредно.
- **Включить.** «Включить туннель» доступно после успешной проверки не старше суток. Запускается задача `tunnelon` — рецепт входа с туннелем; флаг `relay_tunnel` пишет её последний шаг, так что упавшая задача оставляет прежний выбор, а следующая переустановка возвращает вход к нему.
- **Выключить.** «Выключить туннель» — задача `tunneloff`: сначала nft и nginx переходят на публичный адрес хаба, затем снимается конец туннеля на входе (шаг «Снятие туннеля на входе»), потом на хабе; флаг снимает последний шаг. Подключения не рвутся: правила ufw для нового пути ставит первый шаг рецепта (фаервол идёт до пересылки и туннеля).
- **`deploy --relay-tunnel ID`** сам ставит флаг: без него следующая переустановка сняла бы туннель.

## Новый вход и переустановка с туннелем

С флагом рецепт ставит туннель сам: шаги «Туннель на Hub» и «Туннель до Hub», затем доверие, правила, nginx.
- Если GRE до хаба не проходит (провайдер режет протокол 47), вход не ставится.
- Если пул пересекается с маршрутом или адресом на любом конце, шаг отказывает без изменений.

## Проверить

```bash
# хаб
systemctl status heyearth-tunnel-r6; ip -d link show he-r6; ip -4 addr show dev he-r6; ping -c 3 10.77.0.26
nft get element inet heyearth_ddos allow4 '{ 10.77.0.26 }'; ufw status | grep heyearth-tunnel-6
# вход (с хаба: ключ хаба, known_hosts из servers.ssh_host_key)
systemctl status heyearth-tunnel; ip -d link show he-hub; ping -c 3 10.77.0.25; nft list table ip heyearth_relay
```

## Откатить вручную

- **Вход.**
  - `systemctl disable --now heyearth-tunnel`.
  - Вернуть `/root/.heyearth-relay-tunnel/prev.relay.nft` в `/etc/heyearth/relay.nft`, затем `systemctl reload heyearth-relay`.
  - Вернуть `prev.nginx.conf` в `/etc/nginx/nginx.conf`, затем `nginx -t && systemctl reload nginx`.
  - Или всё сразу: `bash /root/.heyearth-relay-tunnel/revert.sh`.
- **Хаб.**
  - `systemctl disable --now heyearth-tunnel-r6`.
  - `ufw delete` правила `heyearth-tunnel-6`.
  - Убрать строку адреса туннеля из `/etc/nginx/heyearth-relays/<вход>.conf`, затем `nginx -t && systemctl reload nginx`.
  - Или `bash /root/.heyearth-relay-tunnel-6/hub-revert.sh`, пока там лежат копии последнего запуска.

## Смена адреса хаба

Мастер «Адрес хаба» переустанавливает входы. Юниты туннеля на обоих концах переписываются с новым `main_server_host` и перезапускаются. Между шагом хаба и шагом входа туннель лежит секунды, 443/80 в это время идут через backup.
